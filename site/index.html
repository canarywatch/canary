what the numbers mean

tripped means our rules added up to the line (score 7) on a new package, or one unmistakable finding landed in a version only hours old of a trusted name. The lines that did it are on the card. It is our word, not the record's.

confirmed means OSV / OpenSSF carries a malware advisory for exactly that version. Nothing else earns the word.

watch is the quiet list: something tripped but not enough. Never shown as a catch, never named on the wall. Established packages (a year old, or 50k downloads a week) stay there no matter what the heuristics say, unless the hijack rule fires.

The recall number appears once the public record confirms a package the agent has read.

the method

How it works

One loop, four steps, all of it in the open. The code is a single Python package with no build step; the box runs it in a sandbox that cannot write outside its data directory.

The code on GitHub →
01 · feed

New releases, as they land

npm's replicate _changes stream and PyPI's updates and newest-projects RSS, polled every 20 seconds. Only names, no code yet. @types/* is skipped: generated typings, never a payload.

02 · fetch

Bytes, not an install

The tarball or sdist is downloaded and unpacked in memory by an extractor that drops absolute paths, .., symlinks and device files, caps file count, file size and total size, and keeps only the bytes. Nothing touches the disk. Nothing is imported.

03 · read

Seven rules, each with evidence

Install hooks, obfuscation, exfiltration (secret files and a network call), wallet grabs, shell shapes, stray binaries, lookalike names. Base64 blobs that decode to code become virtual files and get read too. Tests, docs and CI files count for nothing unless an install script points at them.

04 · record

Ask the record, then keep asking

Every package is looked up at OSV.dev, which carries the OpenSSF malicious-packages advisories. A hit is confirmed. A tripped catch is re-asked every six hours for a month; when the record catches up, the feed says how many hours after the rules did.

05 · trusted names

Established packages are not shamed

A year old or 50k downloads a week: heuristics alone never put it on the wall; it can only land in the quiet list. The one exception is the hijack rule: a version younger than 72 hours carrying one finding of weight 5 and a score over the line.

06 · corrections

A person can clear a catch

A file on the box, cleared.json, maps a package to a reason. The catch stays visible, marked cleared, with the reason. Nothing is deleted. The number of cleared catches is a public counter, because a scanner that hides its mistakes is not worth reading.

Hard limits

Things the agent cannot do, because the code has no path to them. Read the source; the list is short.

×
Never installs or runs a package

Bytes are read from an in-memory archive. There is no npm install, no pip, no import, no subprocess anywhere in the agent.

×
Never names a package without its lines

A catch is a list of findings, each with a file, a line number and the text. A card without evidence cannot be rendered.

×
Never calls anything confirmed on its own

Confirmed is a word that only a public advisory at OSV / OpenSSF can earn. Our rules can say tripped, and that is all they can say.

×
Never keeps what you paste

The check endpoint parses the text, answers, and drops it. The data directory holds the wall and counters; your dependency file is never written.

×
Never posts, never trades

The agent has no credentials of any kind. No X account, no wallet, no tokens. It writes json files, and that is the whole of its output.

×
Never hides a mistake

Cleared catches stay on the wall with the reason. Misses against the public record are counted and shown as the recall number, even when that number is embarrassing.
